# Отпуск — HR-сервис

Веб-приложение для подачи, согласования и отслеживания заявлений на отпуск. Интерфейс на React + TypeScript, REST API на Express, данные хранятся в SQLite.

## Запуск в Docker

Установите и запустите Docker Desktop, затем в папке проекта один раз выполните:

```bash
docker compose up -d --build
```

Откройте `http://localhost:3001`. Контейнер запускает production-сборку интерфейса и API вместе. SQLite и вложения используются из `server/data`, поэтому сохраняются при пересборке и перезапуске контейнера. Compose автоматически перезапускает сервис, если он завершится или Docker перезапустится.

Чтобы Docker Desktop запускался вместе с Windows, включите в его настройках **Start Docker Desktop when you sign in to your computer**. После этого приложение будет доступно без ручного запуска сервера. Для остановки выполните `docker compose down`; том с данными при этом сохраняется.

## Локальная разработка

Требуется Node.js 20.19+ или 22.12+.

```bash
npm install
npm run dev
```

Откройте `http://localhost:5173`. Команда запускает Vite и API (`http://localhost:3001`); Vite проксирует `/api` на backend. SQLite-файл создаётся автоматически в `server/data/vacations.sqlite`.

Для production-сборки интерфейса выполните `npm run build`. API запускается отдельно командой `npm run dev:api`.

## Демо-доступ

Все демо-пользователи используют пароль `Vacation2026!`.

| Роль | Почта |
| --- | --- |
| Сотрудник | `employee@hr.local` |
| Сотрудник | `employee2@hr.local` |
| Сотрудник | `employee3@hr.local` |
| Руководитель | `manager@hr.local` |
| Руководитель | `manager2@hr.local` |
| HR | `hr@hr.local` |

При первом входе каждый демо-пользователь подключает TOTP через приложение-аутентификатор (Google Authenticator, Microsoft Authenticator и совместимые приложения). QR-код показывается при настройке; после этого при входе нужен одноразовый код. Для существующих учётных записей без MFA настройка будет предложена при следующем входе.

## Возможности

- Сотрудник создаёт заявление с типом отсутствия, диапазоном дат и комментарием.
- Руководитель видит заявления своей команды и согласует или отклоняет их.
- После согласования руководителем заявление поступает на финальное решение HR.
- Для отказа обязателен комментарий; каждое решение сохраняется в истории с автором и временем.
- Заявление открывается в подробной карточке с комментарием сотрудника, вложениями и полной историей решений.
- К заявлению можно приложить до пяти PDF, изображений, TXT или DOC/DOCX-файлов размером до 10 МБ каждый; скачивание проверяет доступ к заявке.
- Руководитель видит и может открыть только заявки сотрудников, привязанных к нему; HR видит все заявки.
- Вход подтверждается TOTP-кодом; коды с повторно использованным временным интервалом отклоняются.
- Доступ к данным и решениям проверяется на API по роли и этапу workflow.
- Интерфейс доступен на русском, английском и казахском языках; выбор сохраняется в браузере.
- Есть светлая и тёмная темы с сохранением предпочтения.
- Кастомные календарь и выбор типа отсутствия адаптированы для мобильных экранов.

Рабочие дни считаются без суббот и воскресений; производственный календарь и праздники в демо не учитываются.

## Структура данных

SQLite содержит таблицы `users`, `requests`, `history` и `attachments`. При первом запуске сервер создаёт демо-учётные записи и схему автоматически. Файлы хранятся вне публичной папки; API отдаёт их только после проверки доступа к заявке. Удалите `server/data/` для сброса локальных данных.

## Для production

Это тестовый MVP: сессии и временные MFA-challenge хранятся в памяти процесса, демо-пароли общие, отсутствуют ограничение частоты входа и интеграция с корпоративным провайдером учётных записей. TOTP-секреты в демо хранятся в SQLite без шифрования на уровне приложения. Перед реальным использованием замените демо-учётные записи и настройте устойчивое хранилище сессий, HTTPS, rate limiting, шифрование секретов, резервное копирование и журналирование.
